# Agent Conventions

Rules for any agentic coding tool (or human) working in this repo. These are
not suggestions — follow them by default; deviate only with an explicit,
stated reason in the commit or PR description.

## Commit Frequently

- Commit after each logically complete unit of work: one module, one panel
  wired end-to-end, one bugfix, one doc section. Do not bundle unrelated
  changes into a single commit.
- Commit message format: `area/file: imperative summary`, e.g.
  `core/export: parse ffmpeg progress lines` or
  `app/ui: add crop panel layout`.
- Prefer several small, easy-to-review commits over one large diff.

## File Size

- Soft target: **~300 lines** per file.
- Hard cap: **500 lines**. Never let a change land that pushes a file over
  this limit.
- When a file approaches ~400 lines, split it by responsibility before
  adding more to it — don't wait until it hits the cap.

## Folder-by-Responsibility

- New code goes into the module that already matches its responsibility
  (see the crate layout in `README.md` / plan history). If nothing fits,
  create a new file or subfolder rather than overloading an existing one.
- Group related files into folders (e.g. `panels/`, `bindings/panels/`,
  `timeline/`) instead of flattening everything into one directory.

## Keep Files Dumb

- One responsibility per file/module. Prefer many small, obviously-named
  functions and structs over a few large, multi-purpose ones.
- `main.rs` and `app_state.rs` in `clipforge-app` must stay thin — they wire
  things together, they don't contain logic. Business logic belongs in
  `bindings/*`, `clipforge-core`, or `clipforge-player`.

## Rust Tooling

- Run `cargo fmt` before every commit.
- `cargo clippy --all-targets --all-features -- -D warnings` must pass
  clean before a commit lands.
- `cargo test -p clipforge-core` must pass; this crate has no Slint/mpv
  dependency so it runs headlessly in CI on both Linux and Windows.
- Pre-commit checklist:
  `cargo fmt --check` → `cargo clippy -- -D warnings` → `cargo test -p clipforge-core` → commit.

## Slint Conventions

- One component per `.slint` file; the filename matches the component name
  (e.g. `crop_panel.slint` defines `CropPanel`).
- All colors, radii, spacing, and fonts come from the `global Theme` tokens
  defined in `theme.slint` — never hardcode a color or pixel value directly
  in a component file.

## FFmpeg / FFprobe Wrapper Testing

- `ffmpeg_args.rs` functions are pure (`Project -> Vec<String>`) and unit
  tested with plain assertions — no process spawning in unit tests.
- `probe.rs` is tested against recorded ffprobe JSON fixtures under
  `crates/clipforge-core/tests/fixtures/`, not a live `ffprobe` binary.
- Real-process integration tests (actually invoking `ffmpeg`/`ffprobe`) are
  marked `#[ignore]` by default and only run in an explicit CI job where the
  binaries are guaranteed installed.

## Error Handling

- Use `thiserror` for typed errors in `clipforge-core` and
  `clipforge-player`.
- Use `anyhow` only at the app boundary (`main.rs`, `bindings/*`) to add
  context when propagating errors up to the UI.
- Never `unwrap()` or `panic!()` on a user-triggered path (opening a file,
  exporting, etc.) — surface the error as a UI error/toast state instead.

## Unsafe Containment

- All `unsafe` code and FFI bindings live in `clipforge-player` only.
  Nothing in `clipforge-core` or `clipforge-app` should need `unsafe`.

## Build Artifacts

- `target/` and `dist/` are gitignored.
- Code generated by `build.rs` (from `.slint` files) is never hand-edited or
  committed.
- Packaging outputs (AppImage, MSI, etc.) build into `dist/`.

## Dependency Hygiene

- Shared crate versions are pinned once via `[workspace.dependencies]` in
  the root `Cargo.toml`.
- Don't add a new crate for something FFmpeg or mpv already provides.

## Documentation

- Every public item in `clipforge-core` and `clipforge-player` gets a `///`
  doc comment — these are the reusable, UI-agnostic layers.
- Every `.slint` file starts with a short header comment describing the
  component's role.
